# 국내 플랫폼 붙여넣기 이주 — 설계 (2026-10-11)

제작자가 제타·엘린·케이브덕·베이비챗·크랙에 만든 **자기 캐릭터**를, 그 사이트 편집 화면에서 칸마다 복사해 붙여 넣어 shizue 플롯으로 옮기는 기능의 설계다.
근거 자료(사이트별 칸 지도, 독점 제도, 테스트 체크리스트)는 `KR-PLATFORM-MIGRATION.md`에 있다. 아직 구현되지 않은 기능이므로 현재 상태의 기준은 여전히 `ARCHITECTURE.md`다.

## 1. 목표와 비목표

**목표**
- 제작자가 원본 편집 화면을 옆에 띄워 두고, **같은 칸 배치**의 폼에 칸마다 붙여 넣으면 플롯이 완성된다.
- 붙여 넣은 결과가 우리 규약(발화 규약, 치환자, 이미지 참조, 로어북)으로 바뀐 모습을 **만들기 전에** 본다.
- 잃는 것은 숨기지 않는다. 대응이 없는 칸은 미리보기에서 표시하고 원문을 내려받게 한다.
- 권리 장치는 지금 것을 그대로 쓴다. 독점 확인만 앞에 하나 더한다.

**비목표 (D13)**
- 원본 사이트에서 무엇이든 서버가 가져오는 일. 다섯 곳 모두 내보내기가 없고 프롬프트는 비공개다. 공개 페이지 크롤링이나 비공개 API 호출은 하지 않는다.
- LLM으로 다듬어 옮기기. 결정적 변환만 한다(사용자 플랜의 사용량을 쓰지 않고, 같은 입력은 같은 결과). 나중에 "AI로 다듬기"를 별도 버튼으로 얹을 수 있다.
- 원본 양식으로 되돌려 내보내기. 우리의 내보내기는 카드 형식이다.
- 남의 캐릭터. 프롬프트가 보이지 않으니 애초에 원문이 없고, 확인 문항이 이를 명시한다.

## 2. 사용자 흐름

진입: `/plots`의 가져오기 묶음에 **"다른 플랫폼에서 옮기기"**를 더한다(카드 파일, RisuRealm, SillyTavern 옆). 라우트 `/[locale]/plots/import/paste` → `/[locale]/plots/import/paste/[platform]`.

1. **사이트 고르기** — 다섯 사이트 카드. 1단계에는 제타·엘린만 활성.
2. **확인** — 사이트별 문항을 모두 체크해야 다음으로 간다(D8, 문항은 §7).
   - 원본 공개 페이지 주소(선택). 넣으면 사이트별 모양으로 검증해 출처로 기록한다.
3. **붙여넣기** — 원본 편집 화면과 같은 순서·이름의 칸.
   - 칸마다 "원본의 ○○ 칸을 전체 선택해 복사" 안내와 원본 한도(안내용), 우리 한도(집행용)를 표시한다.
   - 반복 칸(인물, 첫 메시지, 로어, 상황 예시, 대화 프로필)은 행 추가·삭제·순서 이동, 키보드로 다음 행 추가.
   - 키워드 칸은 `,` `|` 줄바꿈으로 자동 분리한다.
   - 선택형 칸(제타 스타일 탭)은 붙여넣기가 아니라 **원본과 같은 선택지**를 다시 고른다. 라벨이 우리 것과 같아 1:1이다(§5.1).
4. **이미지(선택)** — 파일을 끌어다 놓고 그림마다 **원본 참조 이름**(파일 이름에서 확장자를 뺀 값이 기본값)과 설명을 적는다. 인물 아바타도 여기서 고른다.
5. **미리보기** — 만들어질 플롯을 스튜디오처럼 보여 준다.
   - 도입부와 예시는 실제 발화 파서로 그린다(누가 말하는지 보이게).
   - 칸마다 화자 모드(D6)와 정규화 토글을 바꿀 수 있다.
   - 경고 목록: 한도 초과·잘림, `Guest`/`사용자` 같은 치환된 이름, 로스터에 없는 화자, 대응 없는 칸, 컴포넌트 서브셋 위반, 이미 가져온 초안(D12).
6. **만들기** — `POST /api/plots/migrate` → 이미지 업로드 → 결과 화면.
   - 결과 화면: 스튜디오 링크, 잃은 것 요약, **보존 원문 내려받기**(.txt, D10).

폼은 단계마다 `localStorage`에 사이트별로 자동 저장한다(D11). 저장소 접근은 모두 try/catch로 감싸고, 실패해도 폼은 동작한다. 만들기에 성공하면 그 사이트의 저장본을 지운다.

## 3. 구조

### 3.1 사이트 = 데이터 (`@shizue/core/migrate`, D1·D2)

브라우저에서도 도는 순수 모듈이다(Buffer·fs 없음). 서브패스로만 내보내 웹 번들이 필요한 페이지에서만 끌어온다.

```ts
type MigrationPlatform = 'zeta' | 'elyn' | 'caveduck' | 'babechat' | 'crack';

interface SiteSchema {
  platform: MigrationPlatform;
  sections: SiteSection[];            // 원본 화면의 탭·구획 순서
  confirmations: ConfirmationItem[];  // §7 독점·권리 문항
  sourceUrl: SourceUrlRule;           // §4.3
}
interface SiteSection { id: string; fields: SiteField[]; repeat?: { min: number; max: number } }
interface SiteField {
  id: string;
  label: string;                // 원본 화면 이름 (i18n 키가 아니라 원본의 한국어 그대로)
  aliases?: string[];           // 옛 이름·문서상 이름 — 안내문에 함께 보인다
  kind: 'line' | 'text' | 'turns' | 'keywords' | 'choice' | 'multiChoice' | 'image';
  visibility: 'public' | 'ai' | 'both' | 'meta';
  sourceLimit?: { chars?: number; bytes?: number; unverified?: boolean };  // 안내용
  options?: { value: string; label: string }[];
}

type SiteInput = Record<string, unknown>;   // 칸 id → 값, 반복 구획은 배열
interface SiteMapper {
  toDraft(input: SiteInput, options: ConvertOptions): { draft: MigrationDraft; warnings: MigrationWarning[]; preserved: PreservedText[] };
}
```

- 칸 이름·순서·원본 한도는 로그인 뒤 화면에서만 확정된다. 그래서 **집행하지 않는 데이터**로 둔다. 틀린 것이 발견되면 스키마 한 줄을 고친다.
- 우리 한도는 매퍼 출력(`MigrationDraft`)에서 검사한다. 원본이 더 긴 칸은 경고로 나간다.

### 3.2 `MigrationDraft` 계약 (D3)

```ts
interface MigrationDraft {
  platform: MigrationPlatform;
  sourceUrl?: string;                  // 정규화된 공개 페이지 주소
  plot: {
    name: string;
    intro: string;                     // ≤500자 (D15)
    description: string;               // 세계관 설정
    tags: string[];                    // ≤10 × 20자
    intros: string[];                  // ≤10 × 4,000자, 발화 규약 적용 후
    lorebook: LoreEntry[];
    narrator?: NarratorConfig;
    style?: PlotStyle;
    profiles?: { name: string; description: string }[];   // ≤5
    customUi?: PlotCustomUi;           // 엘린 JSX → componentCode
  };
  members: {                           // 1~10
    name: string;
    intro?: string;                    // 독자 소개 ≤500자
    description: string;
    personality?: string;
    mesExample?: string;               // `<START>` 블록
  }[];
}
```

- 서버는 이 모양을 **기존 coercer**로 검증한다: `coerceIntros`, `coerceTags`, `coerceLorebook`, `optionalNarrator`, `optionalStyle`, `optionalProfiles`, `optionalCustomUi`, 소개 한도, 카드는 `coerceCard`. 새 검증 규칙을 만들지 않는다.
- **지문(D12)**: `draftFingerprint(draft)` = 키를 정렬한 정규 JSON 문자열. 웹은 `crypto.subtle`, API는 `node:crypto`로 같은 문자열을 sha256 한다. 웹은 만들기 전에 `POST /api/imports/lookup`으로 "이미 가져온 초안"을 확인한다.

### 3.3 변환 규칙 (`ConvertOptions`)

**화자 (D6)** — 도입부·상황 예시·첫 메시지처럼 장면 글이 들어가는 칸마다 모드를 고른다.
- `auto`(기본): 따옴표 대사(`"…"`, `“…”`)가 있는 줄 → `주화자: ` + 그 줄. 그 밖의 줄 → 내레이터(접두사 없음). 이미 로스터 이름으로 시작하는 줄은 그대로.
- `character`: 비어 있지 않은 줄마다 `주화자: ` (SillyTavern 이주와 같은 규칙).
- `narrator`: 손대지 않음 = 전부 내레이터.
- `verbatim`: 원문 그대로.
- **제타**는 모드 없이 결정적이다: `@이름: …` → `이름: …`, `@: …` → 내레이터 줄. 로스터에 없는 이름은 `이름: …` 그대로 두어 내레이터 글로 남는다(발화 파서 규칙).
- 주화자는 칸마다 고르고, 기본값은 첫 멤버다.

**치환자**
- `{{user}}`·`{{char}}` 그대로.
- `{user}`·`{char}` → `{{user}}`·`{{char}}` (기본 켬, 토글).
- `Guest`(제타 공개 화면)·`사용자`(크랙 비로그인 화면)가 보이면 **경고만** 한다. 일반 단어와 구별할 수 없어 자동 치환하지 않는다.

**이미지 참조 (D5)**
- `img:[x]`(베이비챗) → `{{img::x}}`, `{{img: x}}`(크랙 옛 표기) → `{{img::x}}`, `{{img::x}}`(엘린·크랙) 그대로.
- 에셋은 `name` = 원본 참조 이름으로 올린다. 해석 순서(슬러그 → 이름 → 확장자 뗀 이름 → 접은 슬러그)가 이미 있으므로 본문을 고칠 필요가 없다.

**이미지 목록 로어 (D7)**
- 원본이 설명으로 그림을 고르는 경우, 설명이 있는 에셋으로 constant 로어 엔트리 하나를 만든다. 예:
  `[이미지] 장면에 맞으면 해당 표기를 한 줄로 출력한다.` 뒤에 `{{img::웃음}} — 웃는 얼굴` 같은 줄을 나열.
- 기본 켬: 제타·케이브덕·베이비챗(자동 출력)·크랙 배치표. 엘린은 원본이 수동 `{{img::}}`를 쓰는 경우가 많아 기본 끔.
- 비용: 매 턴 토큰을 쓴다. 미리보기에 엔트리 길이를 보인다.

**키워드**: `,` `|` 줄바꿈으로 분리, 앞뒤 공백 제거, 중복 제거.

**로어 항목 이름**: 우리 `LoreEntry`에는 이름(주석) 칸이 없다. 원본 이름은 버리고 보존 목록에 남긴다(베이비챗은 원래 AI에 보내지 않고, 다른 곳도 대부분 표시용이다). 스튜디오에서 항목을 알아보기 어려워지면 `LoreEntry.comment` 추가를 따로 검토한다.

**한도**: 우리 한도를 넘는 값은 문장 경계(마침표·물음표·느낌표·줄바꿈)에서 자르고 경고, 잘린 원문은 보존 목록으로 간다. 도입부는 4,000자, 플롯 소개 500자, 인물 소개 500자, 태그 20자.

## 4. API

### 4.1 `POST /api/plots/migrate` (D4)

```
{ platform, sourceUrl?, confirmations: { ownWork: true, notExclusive: true }, draft: MigrationDraft }
→ 201 <POST /api/plots와 같은 소유자 플롯 JSON>
```

- `confirmations` 둘 중 하나라도 true가 아니면 400 `migration_unconfirmed`.
- `platform` 열거, `sourceUrl`은 §4.3 검증(실패 시 400 `invalid_request`).
- 한 트랜잭션: 비공개 플롯 생성 → 멤버 삽입. 멤버마다 `imported_from = {fileName: '<platform> 붙여넣기', sha256: <지문>, sourceUrl?, importedAt, platform, method: 'paste'}`.
  - `imported_from`이 찍히므로 발행·공개 플롯 임포트의 권리 확인 게이트가 그대로 걸린다.
- JSON 본문 한도 5MB 그대로. 엘린 무제한 프롬프트도 이 안에 든다.
- 아바타·이미지는 만든 뒤 기존 업로드 라우트로 올린다(§4.2). 실패해도 플롯은 남고, 결과 화면이 재시도를 제공한다.

### 4.2 에셋 업로드에 `name` 추가 (D5)

`POST /api/plots/:id/assets`에 선택 multipart 필드 `name`(원본 참조 이름, 100자)을 더한다. 컬럼 `plot_assets.name`은 이미 있다(카드 임포트용). 슬러그는 지금처럼 따로 받는다.

### 4.3 출처 주소 검증을 core로 (D18)

`@shizue/core/source-url`에 사이트별 규칙을 둔다. API와 웹이 같은 함수를 쓰며, Realm 검증기도 여기로 옮긴다(지금은 `apps/api/src/realm.ts`와 `apps/web/src/lib/realm.ts`에 중복).

| 사이트 | 받는 모양 | 저장 모양 | 근거 |
|---|---|---|---|
| 제타 | `https://zeta-ai.io/{locale}/plots/<uuid>/profile` | `https://zeta-ai.io/ko/plots/<uuid>/profile` | 공개 페이지 관찰 |
| 케이브덕 | `https://caveduck.io/{locale}/characters/<uuid>` | `https://caveduck.io/ko/characters/<uuid>` | 공개 페이지 관찰 |

### 4.4 `ImportProvenance` 확장

`platform?: string`, `method?: 'file' | 'url' | 'backup' | 'paste'`를 선택 필드로 더한다. jsonb라 마이그레이션이 없다. 기존 행은 둘 다 없음(= 파일 임포트로 읽는다).

- **케이브덕**: 에피소드 ×3 → 도입부 ×3(나눠쓰기 말풍선은 행마다 화자 선택), 에피소드 "비밀" → `intros[i].note`(D16), 문체 가이드 → 내레이터 `voice`, 페르소나 가이드 → 추천 프로필, 예시 대화 쌍 → 예시 대화, 로어북(키워드 `|` 분리), 사용자 별도 설명 → 상세 소개(D15), 위젯 → 보존.
- **베이비챗**: 시작 설정 ×3 → 도입부(첫 상황 = 내레이터 줄, 첫 대사 = `이름:` 줄), 상세 프롬프트 → 1:1은 멤버 설정·시뮬레이션은 세계관 설정, 로어 항목(제목은 AI에 안 가므로 주석), `img:[slug]` 정규화, 상세 정보 칩 → 멤버 소개, 플레이 가이드 → 플롯 소개, 추천 답변 → 보존.
- **크랙**: 스토리/캐릭터 두 스키마. 시작 설정 → 도입부 + "시작 상황" → `intros[i].note`, 키워드북 → 로어북, `{{img: x}}` 정규화, 스탯·엔딩·단축어 → 보존. 크랙 오리지널은 확인 단계에서 **진행 불가**.

## 6. 제품 갭 두 가지

### 6.1 상세 소개 (D15)

다섯 곳 중 네 곳이 긴 공개 소개를 갖는다: 케이브덕 별도 설명 15,000자, 제타 소개글 10,000자, 엘린 소개말 9,000자, 크랙 상세 설명 1,000자. 우리 플롯 소개는 500자다.
- **1단계**: 500자에서 문장 경계로 자르고 경고, 원문은 보존 목록에. 스키마 변경 없음.
- **2단계**: `plots.details`(독자용 마크다운, 10,000자, 기존 새니타이저로 그림)를 추가하고, 공개 플롯 페이지의 소개 아래에 펼쳐 보이기. 이주와 무관하게 제작자 경쟁력 요소다.
- 대안: `intro` 한도를 올리기 — 탐색 카드·미리보기가 짧은 소개를 전제로 하므로 비권장.

### 6.2 도입부별 숨은 설정 (D16)

케이브덕 에피소드 "비밀", 크랙 "시작 상황"은 도입부마다 다른 AI 전용 설정이다. 우리 도입부는 메시지일 뿐이다.
- **설계**: `plots.intros`의 원소를 `string | {text, note?}`로 넓힌다(API는 두 모양 모두 받음, 저장은 객체로 정규화하는 마이그레이션). 조립기는 현재 경로의 **루트가 몇 번째 도입부인지**로 그 노트만 `[시작 설정]` 블록으로 넣는다. 도입부는 parent-null 루트라 경로에서 바로 알 수 있다.
- **2단계에 케이브덕·크랙 매퍼와 함께** 낸다. 그 전에는 해당 사이트를 열지 않으므로 잘못된 대체(constant 로어로 모든 도입부에 적용)를 쓸 일이 없다.
- 카드 내보내기에는 노트가 나가지 않는다(CCv3에 대응 칸이 없음). 로어 엔트리로 내보내는 것은 추후 결정.

## 7. 확인 단계 문항 (D8)

모든 사이트 공통:
- [ ] 이 캐릭터는 **내가 만들었다**(다른 사람의 캐릭터를 옮기지 않는다).
- [ ] 원작이 있는 2차 창작이라면, 공개 전에 원저작권자의 권리를 확인해야 한다는 것을 안다.

사이트별 독점 제도 (`KR-PLATFORM-MIGRATION.md` §4):
- 제타: 없음.
- 엘린: [ ] ELYN ONLY로 지정하지 않았거나 지정 후 90일이 지났다.
- 케이브덕: [ ] 오리지널 캐릭터가 아니거나, 3개월이 지나 직접 해제했다.
- 베이비챗: [ ] B ONLY가 아니거나 100일이 지났다.
- 크랙: [ ] 크랙 온리가 아니거나 18개월이 지났다. **크랙 오리지널(저작권 양도)은 선택지에서 "진행 불가"로 막는다.**

API는 `confirmations.ownWork`·`notExclusive`가 true일 때만 받는다. 기록은 남기지 않는다(멤버의 `imported_from`과 발행 시 `rights_confirmed_at`이 기록이다).

## 8. 보안·개인정보

- 붙여 넣은 글은 스튜디오에서 직접 쓴 글과 같은 경로로 저장·렌더된다(마크다운·새니타이저·발화 파서). 새 렌더링 표면이 없다.
- 엘린 JSX는 기존 샌드박스(불투명 오리진 iframe 안의 워커)에서만 돈다. 서브셋 검사는 안내용이고 경계는 격리다.
- 서버는 원본 사이트에 아무 요청도 보내지 않는다. 출처 주소는 가져온 사람의 말로 기록될 뿐이다.
- localStorage 저장본은 그 브라우저에만 남는다. 결과 화면과 사이트 고르기 화면에 "저장본 지우기"를 둔다.

## 9. 단계와 검증 기준

**1단계 — 제타·엘린**
- core: `@shizue/core/migrate`(스키마 2개, 매퍼 2개, 변환 규칙, `draftFingerprint`), `@shizue/core/source-url`(Realm 이전 포함).
  - 검증: 사이트별 합성 입력 → 기대 `MigrationDraft` 스냅숏 테스트. 화자 모드 4종, 제타 `@` 규칙, 치환자·키워드·이미지 참조 정규화, 한도 자르기와 보존 목록, 엘린 로어 고급 설정 매핑, 구획 나누기, JSX 서브셋 경고.
- API: `POST /api/plots/migrate`, 에셋 `name`, `ImportProvenance` 확장.
  - 검증: 생성 성공(비공개, 멤버마다 `imported_from`), `migration_unconfirmed`, 잘못된 출처 주소, coercer가 거부하는 초안, 같은 지문의 lookup 적중, 발행 시 권리 게이트가 걸림, 에셋 `name`으로 `{{img::키}}`가 풀림.
- 웹: 사이트 고르기·확인·공통 폼·이미지·미리보기·결과 화면, 자동 저장, ko/en/ja.
  - 검증: 오케스트레이션 단위 테스트(목 fetch), e2e 1개(제타 합성 입력을 폼에 붙여 넣어 플롯 생성 → 스튜디오와 채팅에서 화자·로어·스타일 확인).
- **사용자가 필요한 단계는 하나뿐**: 실제 제타·엘린 계정으로 자기 캐릭터 하나를 옮겨 보는 것. 칸 이름·순서·클립보드 형태가 스키마와 다르면 스키마 데이터만 고친다.

**2단계 — 케이브덕·베이비챗·크랙 + 상세 소개 + 도입부 노트**
- 스키마 3개(크랙은 스토리·캐릭터 둘), 나눠쓰기 말풍선 행 UI.
- `plots.details`, `intros[i].note`와 조립기 변경(마이그레이션 1개).
- 검증: 위와 같은 매퍼 테스트, 조립기가 현재 경로의 도입부 노트만 넣는지, 상세 소개 렌더·새니타이즈, e2e 1개(케이브덕).

## 10. 남은 불확실성

- 원본 칸 이름·순서·한도·클립보드 형태 — 스키마 데이터로 흡수(D1·D2). 1단계 실사용 한 번으로 확정.
- 엘린 공개 페이지 주소 모양 — 호스트만 검사(§4.3).
- 엘린 JSX와 우리 런타임의 호환 범위 — 서브셋 검사로 드러남. 허용 훅 차이가 크면 2단계에 호환 shim 검토.
- "이미지 목록" 로어의 효과 — 토큰 비용 대비 출력 품질은 1단계 사용 후 판단(끌 수 있음).
