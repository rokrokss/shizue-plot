# 국내 플랫폼 이주 — 사이트별 칸 지도와 테스트 체크리스트 (2026-10-11 스냅숏)

케이브덕·베이비챗·제타·크랙·엘린에서 **제작자가 자기 캐릭터를 붙여넣기로 옮겨 오는 기능**을 설계하기 위한 리서치 스냅숏이다.
구현의 기준은 `ARCHITECTURE.md`이고, 이 문서는 시점이 지나면 낡는다.

조사 방법: 공식 도움말·공지·약관, 로그인 없이 보이는 공개 페이지, 커뮤니티 글(디시·아카·note.com·나무위키). 다섯 곳 모두 제작 화면은 로그인해야 열리므로, **칸 이름·순서·한도는 앱 안에서 실측해야 확정된다**(§6).
출처 표기: [공식] 공식 문서·공지·약관, [관찰] 2026-10-11 공개 페이지 직접 확인, [커뮤] 커뮤니티, [추정] 위에서 끌어낸 추론.

## 0. 요약

- **다섯 곳 모두 캐릭터 설정을 내보내는 기능이 없다.** 제작자가 편집 화면에서 **칸마다 따로** 복사해야 한다. 프롬프트·로어북은 비공개라 원문을 가진 사람은 제작자 본인뿐이다(예외: 케이브덕 캐릭터 설명·세계관은 "별도 설명"을 켜지 않으면 공개, 제타 플롯 설명은 "나만의 소개글 꾸미기"를 끄면 공개, 제타 공개 설정집은 전문 공개).
- 그래서 기능의 모양은 **"사이트 선택 → 그 사이트 편집 화면과 같은 칸 배치의 붙여넣기 폼 → 우리 필드로 매핑 → 미리보기 → 비공개 플롯 생성"**이다. 한 덩어리를 붙여 넣어 자동으로 쪼개는 파서는 맞지 않는다(칸 경계가 복사본에 남지 않는다).
- 경쟁 사례: 루덴서가 2026-09-17부터 케이브덕·로판AI·엘린·티팟·루나톡 5곳의 복사·붙여넣기 가져오기(원본 유지 / 루덴서 변환 두 모드)와 베타 내보내기를 제공한다([공지](https://gall.dcinside.com/mgallery/board/view/?id=aiotomechatting&no=18049)). 제타·크랙·베이비챗은 그 목록에 없다.
- **독점 제도가 이주를 막는 경우가 있다**(§4). 가져오기 전에 확인 문항이 필요하다. 그 밖의 일반 작품은 다섯 곳 약관 모두 "권리는 제작자에게, 플랫폼에는 비독점 이용 허락" 구조라 제작자 본인의 이주는 가능하다고 본다(법률 자문 아님).
- 구조가 우리와 가장 비슷한 곳은 **제타**(플롯 단위, 등장인물 최대 10, 스타일 탭이 우리 스타일 열거값과 거의 1:1, `@이름:` 화자 규약)와 **엘린**(첫 메시지 여러 개, `{{img::키}}`, JSX 컴포넌트를 메시지 안 태그로 호출)이다.

## 1. 우리 쪽 받을 자리

| shizue 필드 | 한도 | 대상 |
|---|---|---|
| 플롯 이름 | — | 독자 |
| 플롯 소개(`intro`) | **500자** | 독자 |
| 세계관 설정(`description`) | — | 모델 |
| 도입부(`intros`) | 10개 × 4,000자 | 둘 다 (발화 규약 적용) |
| 플롯 로어북 | 엔트리: 키·보조 키·constant·정규식·depth·role·확률·그룹·스캔 깊이·sticky/cooldown/delay | 모델 |
| 태그 | 10개 × 20자 | 독자 |
| 추천 프로필 | 5개 (이름 30자, 소개 1,000자) — 고르면 독자의 페르소나로 복사되어 프롬프트에 실린다 | 둘 다 |
| 내레이터 | `{voice, pov}` | 모델 |

| 커스텀 UI | 표시 스크립트, 기본 변수, JSX 컴포넌트(샌드박스) | 화면 |
| 에셋 | 100개, `{{img::슬러그}}`(+카드 원래 이름), 해금 조건 | 화면 |
| 등장인물 × 10 | 이름, 아바타, 독자 소개 500자, 설정, 성격, 예시 대화, 카드 로어북 | 둘 다 |

**대응이 없는 것(이주하면 사라지거나 재구성이 필요한 것):**
- 시작 상황별 **숨은 설정**(케이브덕 에피소드 "비밀", 크랙 "시작 상황", 베이비챗 "첫 상황"의 AI 전용 부분) — 우리 도입부는 메시지일 뿐 도입부별 프롬프트가 없다. 가장 가까운 대응은 플롯 로어북 constant 엔트리(모든 도입부에 적용됨).
- **이미지 설명 기반 자동 출력**(케이브덕·베이비챗·제타·크랙 신버전·엘린 자동 모드) — 우리 프롬프트 조립은 제작자 글(세계관·로어)의 `{{img::…}}`까지 지우므로, 모델은 에셋 목록도 설정 속 이미지 출력 지시도 보지 못한다.
- 제작자 정의 **스탯·엔딩·퀘스트·단축어·추천 답변**(크랙·제타 플러그인·베이비챗) — 관계 스탯은 고정 6축이다.
- 500자를 넘는 **공개 소개**(케이브덕 별도 설명 15,000자·코멘트 30,000자, 제타 소개글 10,000자, 엘린 소개말 9,000자).

## 3. 공통 변환 규칙

- **치환자**: `{{user}}`·`{{char}}`는 그대로. `{user}`·`{char}`(크랙 관행)는 이중 중괄호로 고칠지 미리보기에서 묻는다. 공개 화면에서 복사한 경우 섞여 들어오는 `Guest`(제타)·`사용자`(크랙)를 경고한다.
- **화자**:
  - 제타 `@이름: …` → `이름: …`, `@: …` → 접두사 없음(내레이터).
  - 케이브덕 나눠쓰기 말풍선: 캐릭터·엑스트라 → `이름: `, 지문 → 접두사 없음, 플레이어 → 내레이터 줄(`{{user}}: …`는 로스터에 없는 접두사라 내레이터 글로 남는다).
  - 그 밖(엘린·크랙·베이비챗의 `*행동*` + 대사 산문)은 등장인물이 한 명이면 줄마다 `이름: `을 붙인다 — SillyTavern 이주와 같은 규칙. 베이비챗은 첫 상황(내레이터) + 첫 대사(`이름: `)로 나눠 합친다.
- **이미지 참조**: 엘린 `{{img::키}}`, 크랙 `{{img::이름}}`·`{{img: 이름}}`, 베이비챗 `img:[slug]` → `{{img::슬러그}}`. 케이브덕·제타는 텍스트 참조가 없으니(설명 기반 자동) 에셋만 옮기고, 출력 지시는 제작자가 설정에 추가하도록 안내한다.
- **상태창·위젯**: 제타 `InfoBox` 코드 블록, 크랙 코드 블록 상태창, 케이브덕 위젯 HTML은 자동 변환하지 않는다. 원문을 보존해 두고 스타일의 상태창이나 표시 스크립트로 다시 만들도록 안내한다.
- **한도 초과**: 우리 한도(플롯 소개 500자, 도입부 4,000자, 태그 20자)를 넘는 칸은 미리보기에서 표시하고, 자르기 / 세계관 설정으로 옮기기 중 고르게 한다.
- **다른 사람의 것**: 제타 설정집은 남의 것이 연결돼 있을 수 있다. "내가 만든 설정집만 붙여 넣는다"를 확인 문항에 넣는다.

## 5. 루덴서 블랙박스 테스트 체크리스트

목적: 루덴서의 붙여넣기 가져오기가 칸을 어떻게 나누고 바꾸는지, 규칙 기반인지 LLM인지, 무엇을 버리는지 확인한다.
원칙: **본인 계정, 본인이 만든 비공개 테스트 캐릭터만.** 자동화·크롤링·요청 위조 금지. 루덴서 약관의 리버스 엔지니어링 조항을 먼저 확인한다. 코드는 보더라도 복사하지 않는다.

### 5.1 테스트 캐릭터 만들기

각 원본 사이트(루덴서 지원 대상인 케이브덕·엘린부터)에 비공개 캐릭터를 하나씩 만들고, 칸마다 표식을 넣는다.

- 표식: `⟪사이트코드-칸번호⟫` — 사이트코드 CD(케이브덕) · EL(엘린) · BC(베이비챗) · ZT(제타) · CR(크랙).
- 긴 칸은 앞뒤를 감싼다: `⟪CD-04 시작⟫ … ⟪CD-04 끝⟫` (잘림 확인).
- 모든 긴 칸에 공통 샘플을 넣는다:

```
⟪XX-NN 시작⟫
## 헤더 하나
{{user}}와 {{char}}가 만났다. {user}도 적어 둔다.
*문을 연다.* "안녕?" '속으로 생각한다.'
줄바꿈 셋 아래


영문 한 줄 English line 🙂
⟪XX-NN 끝⟫
```

- 사이트 고유 문법도 한 줄씩: 제타 `@캐릭터명: 대사` / `@: 내레이션`, 엘린 `{{img::참조키}}`, 크랙 `{{img::이름}}`, 베이비챗 `img:[slug]`, 제타·크랙 상태창 코드 블록.

칸 번호 예(케이브덕): CD-01 이름, CD-02 캐릭터 설명, CD-03 세계관 제목, CD-04 세계관 내용, CD-05~07 에피소드 1~3 내용, CD-08~10 에피소드 비밀, CD-11 문체 가이드, CD-12 예시 대화 1(사용자), CD-13 예시 대화 1(캐릭터), CD-14~16 로어북 항목 1~3(키워드 `키워드A|키워드B`), CD-17 별도 설명, CD-18 한 줄 소개, CD-19 크리에이터 코멘트.
엘린: EL-01 이름, EL-02 소개말, EL-03 프롬프트(`# 캐릭터` / `## 이름` 구획 포함), EL-04~06 첫 메시지 1~3, EL-07~09 로어 1~3(고급 설정: 그룹·우선순위·의존성·"찾았을 때 비활성화" 각각 하나씩), EL-10 JSX 컴포넌트 1개 + 프롬프트 속 호출 지침, EL-11 이미지 설명.

| T7 | 왕복 | 루덴서 → 원본 사이트 양식 내보내기(베타) → 원본 사이트에 붙여넣기 | 표식 위치 비교, 손실 |
| T8 | 권리 안내 | 가져오기·공개 흐름 | 독점 제도·권리 확인 안내가 있는지, 어떤 문구인지 |

기록 양식: `| 테스트 | 사이트 | 레인 | 표식 | 원본 칸 | 도착 칸 | 변형 | 메모 |`

## 6. 앱 안에서 실측해야 할 것

- 크랙 메인 프롬프트 한도(3,000~7,000자 혼재)와 템플릿·유형별 차이.
- 제타 2,400자를 어떤 칸들이 함께 쓰는지, 상황 예시 한도, 인트로를 텍스트로 복사할 때 화자 정보가 따라오는지.
- 베이비챗 상세 프롬프트 한도(5,000/6,000/7,000), 로어북 항목 수(50/100/무제한), "상세 프롬프트"와 "프롬프트" 칸의 관계, 커스텀 템플릿 두 종의 차이.
- 케이브덕 예시 대화 개수, 한 줄 소개·문체 가이드 길이, 로어북 키워드 길이(20/50자).
- 엘린 첫 메시지 개수(10은 나무위키만), 로어 250개, 제작 화면의 실제 칸 이름·순서, JSX 런타임에서 허용되는 훅.
- 다섯 곳 모두: 칸을 복사할 때 줄바꿈·마크다운이 그대로 클립보드에 오는지.
