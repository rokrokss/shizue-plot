# shizue-plot — repository guide

One pnpm workspace for character chat. This file is the table of contents;
[apps/plot/docs/ARCHITECTURE.md](apps/plot/docs/ARCHITECTURE.md) owns the
product's behavior and [docs/PLATFORM.md](docs/PLATFORM.md) owns the exported
chat format.

## Workspace layout

| Path | Package | Purpose |
|---|---|---|
| `packages/contracts` | `@shizue/contracts` | zod schemas and types for chat export |
| `apps/plot` | `@shizue/plot` | Script aggregator and unit suite |
| `apps/plot/apps/{api,web,e2e}` | `@shizue/api`, `@shizue/web`, `@shizue/e2e` | Hono API, Next app, browser tests |
| `apps/plot/apps/extension` | — | Chrome sign-in helper for Sign in with ChatGPT |
| `apps/plot/packages/{core,db,llm}` | `@shizue/core`, `@shizue/db`, `@shizue/llm` | Cards/prompts, database, provider clients |

## Commands

Run from the repository root:

```sh
pnpm install
pnpm build
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm db:migrate
make dev
```

The API suite reads `apps/plot/.env` and requires a disposable
`TEST_DATABASE_URL` whose database name ends in `_test`. See README.md §Testing.
`TEST_S3_REQUIRED=1` requires the real S3 driver (the compose RustFS) rather than permitting skips.

For ordinary changes, run the affected test files and relevant typechecks first;
use the full suite for dependency upgrades, cross-cutting changes, and releases.
Keep regression tests for authentication, security, data integrity, and pending
operations. Avoid separate tests for static copy, CSS classes, trivial wrappers,
or behavior already covered at another layer unless they catch a distinct failure.

`apps/plot` has no `build` script: the root builds its packages and apps
in dependency order. Build the libraries before checking an otherwise fresh
checkout because their exports point at `dist/`.

## UI and contracts

Read [docs/design/shizue-ui.md](docs/design/shizue-ui.md) before UI
work. Import chat-export schemas from `@shizue/contracts`; do not duplicate them.
When changing that package, build it and verify the API and web consumers in the
same change. `packages/contracts/dist` is generated by `prepare` during install
and is not committed.

## Local validation

Checks are run locally using the commands above. `make e2e` runs the browser suite.

## House rules

- Korean documents stay Korean; English documents stay English.
- The character-chat schema starts from one initial migration. Existing databases
  must be reset; upgrades from the removed products are unsupported.
- The main checkout is for live testing. Implement in a separate worktree on a
  `codex/` branch; copy `apps/plot/.env` and run `pnpm install` there.
- Do not run tests concurrently against the same scratch database.
- Avoid dev servers in worktrees unless their ports and auth origin are offset.
